# Managed 人工接管的输入法预编辑显示

人工接管时显示本地输入法的组合文字，确认后才把文字发送到
原页面。组合区位于最近一次画面点击附近；重新点击会清掉尚未确认的文字，
也可以点击“完成接管”放弃本次组合。此增量已随 [preview-20261021-79206b3](https://github.com/mikyan/open-browser-use/releases/tag/preview-20261021-79206b3) 发布。
发布 EXE 独立重建；以下浏览器验收属于原冻结构建，本次打包没有重跑网页流程。

## 输入与布局合同

保留原本地 textarea、原生组合事件和选择范围。只在组合期间显示这个输入框，
不另外复制文字到状态栏，也不把候选更新发送到任务页面。每次最终确认继续
使用原 lease/generation 的串行 text 请求及确切原回执；相同内容的两次确认
是两个独立输入，不按文字去重。远端收到已确认文字，不接收本地 composition
生命周期，见[原提交路径](managed-human-ime.md)。

位置使用最近一次有效画面按下的相对坐标，剔除图片留白，再按当前显示尺寸
映射；组合框受画面容器与查看器窗口可见交集约束。resize/scroll 只改变布局，
不改变原值、选区或焦点。组合区不接收鼠标事件，正常画面点击仍进入原输入
通道。最近点击不是远端 caret，不能宣称 Tab、方向键或页面滚动后仍精确跟随
远端插入位置。

新画面按下先撤销旧组合，再设置新锚点；导航、End/Stop 和失去就绪状态时
撤销组合 scope，弹窗/文件选择到来时先撤销再禁用 textarea。明确结束按钮
的 mousedown 保留原输入焦点，由 click 执行撤权，避免按钮自身移焦先确认
组合。普通失焦之前若浏览器已经确认并发送文字，不能撤回或声称从未提交。

## 可复用验证与边界

按[原 IME 入口](managed-human-ime.md#可复用入口)设置构建、扩展、浏览器与
manifest，再设置 `OBU_TEST_HUMAN_IME_MODE=baseline` 或 `acceptance`。
baseline 完成业务也不算功能通过；acceptance 还必须通过布局与两个生命周期
探针。未设置时保留原提交路径验证。原生 CDP 组合命令只用于隔离查看器，
不直接输入任务页，不派发合成 DOM 事件，不操作系统鼠标或剪贴板。

本轮固定 Windows Headless Chromium 156.0.8078.12，不证明 Windows 实际
TSF 候选窗口、远端 caret 跟随、组合中所有导航/失焦顺序或更多平台兼容。
导航/弹窗/chooser 的旧组合退役及边缘布局由确定性测试覆盖，未冒充这些路径
的完整实机验收。全局 Browser Use 对齐目标继续保持进行中。
