# Managed 人工接管的离页确认

开发分支支持在已就绪的独立 managed 页面中回答 `beforeunload`：查看器显示
“留在页面”和“离开页面”。留在页面后可继续编辑原草稿；离开后等待原页面的
新文档和真实画面，再继续操作。Agent 始终暂停，必须完成接管并显式恢复后
才能接续工作。此功能尚未进入 `preview-20261021-3e61b68` 安装包。

## 原文档与决定

根页面链接可能先弹确认框，再开始导航；跨站子 frame 的 `target=_top`
链接可能先发出根导航开始事件，再弹原页面确认框。两种顺序都使用先前已
验证的原文档证明，不以新网址或后继文档授权旧决定。

- 核心固定原 attachment、浏览器 documentId、frame/loader、默认 context
  和事件记录。导航开始撤销旧输入 generation，离页决定有独立的有效期。
- 回答仍使用原 lease/generation/dialogId 的唯一 typed 通道。原
  `Page.javascriptDialogClosed.result` 和实际处理 Promise/ACK 分别等待，
  请求 accept 值本身不能代替浏览器的实际结果。
- Stay 要求旧文档、网址、target、位置、网站权限和原 context 仍一致。
  只恢复原事件对象并刷新同文档观察证据，不推进已交付结果的文档登记；
  新 generation 等待旧操作清理和新的原生画面，旧输入序号不能复活。
- Leave 同步撤销旧决定及输入，随后要求原导航路径的 native commit、
  后继文档证明及新画面。无关 frame 提交或仅有 webNavigation 通知不能代替。
- 同网址迟到通知仍复核原候选和离页证明；不忽略通知，也不重新授权。
  End、超时、第二次歧义导航、文档/context 替换或未知回执撤销旧权限。
  原实际读取和发送仍等待结算，不能用观察超时提前确认清理。

Go 与查看器只为 beforeunload 增加类型和明确按钮，不接收 prompt 文本；
原 alert/confirm/prompt、弹窗累计等待预算、独立输入/回答 ACK 和 End 清理
合同保留。跨站导航开始后的待决定阶段可能暂时撤下旧画面，选择卡片仍可用。

## 保留的失败与边界

原产品 `mbu-mf7bh1`、`mbu-BFMeNn` 自动取消且结束接管的诊断保留；它们
使用发送观察包装，仅证明缺口。首场正式 `mbu-lcCkr2` 在 Stay 续写、Leave
决定后因错误的跨观察来源时间比较失败；原 false 结果和清理证据保持。
修正后按同来源原事件序列、确切决定身份及唯一原回执核对，不使用毫秒容差。
开发期间的迟到网址提示误取消有独立原失败/对照和修复验证。

当前实测是固定 Windows Headless Chromium 156.0.8078.12 的两种普通链接
流程。接管前已有弹窗、尚无原就绪快照、浏览器工具栏关闭/刷新、复杂嵌套或
歧义并发导航、真实公司 Edge、SSO/MFA 和实体桌面焦点行为不由这两场证明。
原对话框预算的边界交错由确定性测试覆盖，本轮没有另跑五分钟等待。
本项不改变 Stop 关闭独立会话的合同，不声明完整 Browser Use 能力对齐。
