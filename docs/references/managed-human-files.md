# 人工接管的文件选择与上传

实验性 managed 查看器在接管期间显示网页发出的原文件选择请求。用户点击
“选择文件”后，通过查看器本地文件选择框提供文件；主程序逐块接收名称和
字节，交给原网页的文件输入节点。网页仍按自身逻辑决定何时提交。

## 使用与边界

等待文件选择时，查看器显示已证明的主页面/子页面和 HTTP(S) 来源；无法
证明时显示来源未提供。来源只是提示，不授权其他页面使用此请求。原按键或
鼠标仍处于按下状态时，先松开再选择文件。等待期间不接纳新的普通页面输入。

每次最多 16 个文件，单文件最多 32 MiB，合计最多 64 MiB；同一浏览器会话
保留最多 256 MiB。支持空文件和同名文件，名称须为有效 Windows 文件名，
最多 240 UTF-8 字节。仅承诺名称与原字节，不恢复原路径、MIME 或修改时间。
目录选择不在本次范围内。

原网页请求最多等待 20 分钟，开始传输后总期限为 10 分钟，两者取早。
每块确认不延长期限。“取消选择”撤销本次请求并保留网页已有文件，不等于
将文件列表清空，也不承诺触发浏览器原生 `cancel` 事件。

本地选择框导致失焦的例外只绑定这次可信点击及原请求；隐藏查看页面、超时、
导航或结束接管会撤销旧选择。晚到的本地选择和旧回执不能影响新的请求。

结束接管后 Agent 仍暂停；显式继续并开启新轮次后，可重新取得结果页并提交
原文件。上传完成后暂存文件必须保留到实际浏览器会话退出，因为网页或 Agent
可能在 End 后才读取 File/FormData。尚未提交的传输在取消、导航或 End 时清理。

## 接口与资源归属

原租约声明固定 `fileChooserVersion: 1`；`pendingFileChooser` 固定
`leaseId/generation/chooserId/multiple` 及可选来源。私有原生节点、frame 和
session 不暴露给查看器。`humanFileBegin/Chunk/Commit/Cancel` 使用独立有界
通道，保留原命令 32 KiB 限制；每块为最多 16 KiB 原字节和严格 base64。

Go 只接收名称和字节，在原 Session 私有目录创建文件；网页不能指定主机
路径。Commit 前先将暂存文件归 Session 持有，再向原节点发送一次
`DOM.setFileInputFiles`。原确认、超时和未知结果均不触发重发。

扩展复用文档图谱与文件输入注册表，在原 attachment 上开启拦截并绑定原
Opening。权限失效与原生资源销毁分开：跳页撤权不代替尚未结算的提交或清理。
已发送 Commit 触发导航时，仍仅在原期限内等原回执。最终关闭须等待原浏览器
退出及控制器清理；删除失败如实报告，不能返回清理成功。

## 验证

冻结构建 `mso-build-4h3l_le5` 通过完整 Go test/vet 和 3,084 项 Node 检查，
绑定 460 份源码输入及 79 份扩展。正式未插桩 `mfc-Xswpjy` 四步全部通过：
主页面单文件、跨进程 iframe 的同名/空文件、取消保持原 FileList、传输中
End 与导航撤销。End 后显式 Resume、新轮次及重新认领保持原 target、
文档和窗口位置；两次原表单唯一 POST 的名称、字节和哈希吻合。
Stop 后 30 个原进程身份、暂存文件与私有注册/管道已清理。
原事件独审 1,393 项、生命周期和来源独审 128 项通过，20 张 PNG 完整解码；
另目视检查原文件选择卡片。两份审计最初的 Stop 字段模板错误保留，
修正后仅重审原记录，没有重跑或改写浏览器结果。

本轮发现重新认领结果页会走普通分组并搬窗，导致后台捕获不返回首帧。
新增独立 `managed-result`/user 归属仅保留已验证、未固定、未分组、普通窗口
原结果页的位置；不改变其他标签的分组模式，已有任务页仍保留原来源身份。
原证明持续到认领结束，移动后移回及文档替换也撤权；重启不恢复旧权限。
该修复通过 93 项定向回归及独立差异检查，正式流程中原 root/iframe
提交点击分别在 114/130 ms 完成，没有延长原 10 秒期限。

清理发送与业务发送分开：原文档有实际销毁证明时，已发出的旧资源清理请求
迟到拒绝不再撤销存活的新文档；原 Promise 仍实际结算。仅父导航、权限撤销
或 session detach 不构成该证明，业务文件提交不使用此例外。该问题保留
真实失败诊断及先红后绿的回归；受影响 231 项检查通过。

集成入口为 `scripts/browser-integration/managed-human-file-chooser-check.mjs`。
设置绝对路径 `OBU_TEST_HOST_BINARY`、`OBU_TEST_EXTENSION_DIR`、
`OBU_TEST_BUILD_MANIFEST`、`OBU_TEST_CHROMIUM_BINARY`，并设置
`OBU_TEST_HUMAN_FILE_CHOOSER_MODE=workflow` 后运行 Node。脚本冻结构建和
测试来源，使用独立资料目录及四个原交付页；必须完成 End 后显式恢复、
重新认领和原表单唯一提交，才算完整通过。

默认 baseline 仅用于旧运行时缺失通道诊断；额外设置
`OBU_TEST_HUMAN_FILE_CHOOSER_DIAGNOSTIC=1` 会观测原清理与动作回执，其
`featurePassed` 始终为 false，不得代替未插桩验收。

真实验收使用独立 Headless Chromium，并向查看器的原本地选择器提供文件；
不操作桌面鼠标或个人浏览器。此方式不能证明 Windows 原生文件框的焦点行为，
普通公司 Edge、其他平台、目录选择和整体能力对齐仍待验证。
