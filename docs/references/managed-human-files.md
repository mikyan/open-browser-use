# 人工接管的文件选择与上传

实验性 managed 查看器在接管期间显示网页发出的原文件选择请求。用户点击
“选择本地文件”后，通过查看器本地文件选择框提供文件；主程序逐块接收名称和
字节，交给原网页的文件输入节点。网页仍按自身逻辑决定何时提交。

当前开发版也支持原网页的目录请求，按钮显示“选择本地文件夹”，使用查看器
本地目录选择框，保留所选单一根目录内的文件层级。目录上传尚未进入最新
`preview-20261021-805b1a8` 完整包；以下目录能力描述针对当前开发源码。

## 使用与边界

等待文件选择时，查看器显示已证明的主页面/子页面和 HTTP(S) 来源；无法
证明时显示来源未提供。来源只是提示，不授权其他页面使用此请求。原按键或
鼠标仍处于按下状态时，先松开再选择文件。等待期间不接纳新的普通页面输入。

每次最多 16 个文件，单文件最多 32 MiB，合计最多 64 MiB；同一浏览器会话
保留最多 256 MiB。支持空文件和同名文件，名称须为有效 Windows 文件名，
最多 240 UTF-8 字节。普通文件模式只承诺名称与原字节，不恢复原路径。
目录模式另保留 `webkitRelativePath`，包括所选根目录名和嵌套层级；不同
子目录可含同名文件。相对路径最多 1,024 UTF-8 字节、16 段，段数包含根目录
和文件名，每段仍受文件名限制。拒绝跨根、重复路径、大小写别名及文件与目录
冲突，不修改名称来规避冲突。空文件正常上传，空目录不上传，也不伪造占位文件。
两种模式均不承诺保留 MIME 或修改时间。

原网页请求最多等待 20 分钟，开始传输后总期限为 10 分钟，两者取早。
每块确认不延长期限。“取消选择”撤销本次请求并保留网页已有文件，不等于
将文件列表清空，也不承诺触发浏览器原生 `cancel` 事件。

本地选择框导致失焦的例外只绑定这次可信点击及原请求；隐藏查看页面、超时、
导航或结束接管会撤销旧选择。收到原撤权状态后不再续传旧选择，也不将其提交
给新页面；晚到的本地选择和旧回执不能影响新的请求。原生 `frameNavigated`
事件与查看器收到撤权状态之间仍可能有旧暂存块，不承诺该时间段零传输。
已发出的块只属于旧传输，清理须等待其实际写入结束。

结束接管后 Agent 仍暂停；显式继续并开启新轮次后，可重新取得结果页并提交
原文件。一旦发起 Commit，暂存文件必须保留到实际浏览器会话退出，因为网页
或 Agent 可能在 End 后才读取 File/FormData，未知提交结果也不能提前删除。
尚未提交的传输在取消、导航或 End 时等待实际写入结束后清理整个私有传输目录。

## 接口与资源归属

新租约声明固定 `fileChooserVersion: 2`；`pendingFileChooser` 固定
`leaseId/generation/chooserId/multiple/directory` 及可选来源。v2 的 `directory`
必须为布尔值；Go 和查看器仍兼容 v1 普通文件请求，v1 不带该字段。模式来自
原 Opening 所指向节点的实际属性，不从事件的单选/多选模式推断目录；目录
节点即使 `multiple=false`，也可接收所选根目录中的多个文件。
私有原生节点、frame 和 session 不暴露给查看器。
`humanFileBegin/Chunk/Commit/Cancel` 使用独立有界通道，保留原命令 32 KiB
限制；每块为最多 16 KiB 原字节和严格 base64。Begin 的普通文件清单为
`name/size`，目录清单另含 `relativePath`，且全部条目必须来自同一根目录。

Go 只接收受限名称、相对路径和字节，在原 Session 私有目录创建文件；网页
不能指定主机绝对路径。普通文件布局仍为 `u/<transferId>/<index>/<name>`，
目录布局为 `u/<transferId>/<relativePath>`。Commit 前先将暂存文件归 Session
持有；目录只将这次传输的唯一服务器根目录交给扩展，向原节点发送一次
`DOM.setFileInputFiles`。普通文件沿用原写入回执；目录必须同时等到原生 ACK、
原节点的可信 `input` 及原资源清理，才返回成功 Commit 回执。仅有 ACK
不能证明目录枚举完成，目录失败不使用普通文件的 ACK 回退。

目录写入在最后一次原文档与权限检查完成、即将调用原生 API 时才标记已发送。
异步准入期间已取消的操作按未发送清理，不能因提前标记而等待一个永远不会
发生的目录事件；真正已发送的操作仍保留原 Promise 和未知结果。原确认、
超时和未知结果均不触发重发。

扩展复用文档图谱与文件输入注册表，在原 attachment 上开启拦截并绑定原
Opening。权限失效与原生资源销毁分开：跳页撤权不代替尚未结算的提交或清理。
已发送 Commit 触发导航时，仍仅在原期限内等原回执。最终关闭须等待原浏览器
退出及控制器清理；删除失败如实报告，不能返回清理成功。

## 当前开发版目录上传验证

旧运行时基线 `mfc-1kEEEz` 实际退出 1，分类为已有普通文件通道但拒绝目录。
原生 Opening 和三次 move/down/up ACK 均已记录；自动 End 与按钮 End
都返回 `BACKEND_UNAVAILABLE`，没有成功 End 或 after/FileList 记录。
因此不能把最终文件列表未变或自动退休写成通过；其 `completed`、
`diagnosticCompleted`、`featurePassed` 均为 false。独立 Stop 返回 stopped，
原浏览器、native 及 Job 退出证据仍保留，不能用清理成功覆盖业务失败。

冻结构建 `mso-build-ow4285ux` 通过完整 Go test/vet 与 3,326 项 Node 检查，
其中查看器 UI 276 项，绑定 471 份源码和 80 份扩展文件。正式未插桩目录流程
`mfc-nSCjTV` 与同构建普通文件回归 `mfc-HSHFfg` 均实际退出 0；两场均完成
原四页流程及 Stop。独立事件/业务审计分别通过 1,380/1,299 项，来源与
生命周期审计分别通过 102/97 项。根代理检查两张目录选择卡截图，显示
清晰；像素检查不替代原可信 input、文件字节或系统焦点证据。
导航撤权以查看器收到原状态为边界：原 native 导航到状态传播之间仍有
7/6 个旧暂存 chunk；状态收到后无新 chunk 或提交。已提交树的保留由
提交后、End 后哈希及随后业务 POST 证明，不声称连续监测到 Stop。

目录流程通过查看器原本地目录选择器提供一棵目录树，覆盖中文、多层目录、
不同子目录的同名文件和空文件。主页面节点为 `multiple=true`，真实跨站
OOPIF 节点为 `multiple=false`；两者均收到原相对路径和字节。成功 Commit
回复到达时，原节点可信 input 的独立见证已经存在。取消再次选择保留原树；
End 后显式 Resume、新 SDK 轮次和原页认领后，每页产生唯一业务 POST，
其中实际文件字节与 `webkitRelativePath` 相符。input 见证请求与业务提交
分别记录，不能混算为重复提交。

传输中 End 与夹具控制的导航均未发出 Commit，旧私有树在写入结算后清除。
导航场景证明收到原撤权状态后不续传、不提交给新页；不证明从原生导航事件
发生的瞬间起没有旧暂存块。普通文件回归保留原单文件、OOPIF 同名/空文件、
取消保持 FileList、传输中 End/导航及恢复后唯一业务提交的范围。

## 历史普通文件验收

冻结构建 `mso-build-4h3l_le5` 通过完整 Go test/vet 和 3,084 项 Node 检查，
绑定 460 份源码输入及 79 份扩展。正式未插桩 `mfc-Xswpjy` 四步全部通过：
主页面单文件、跨进程 iframe 的同名/空文件、取消保持原 FileList、传输中
End 与导航撤销。End 后显式 Resume、新轮次及重新认领保持原 target、
文档和窗口位置；两次原表单唯一 POST 的名称、字节和哈希吻合。
Stop 后 30 个原进程身份、暂存文件与私有注册/管道已清理。
原事件独审 1,393 项、生命周期和来源独审 128 项通过，20 张 PNG 完整解码；
另目视检查原文件选择卡片。两份审计最初的 Stop 字段模板错误保留，
修正后仅重审原记录，没有重跑或改写浏览器结果。

当时发现重新认领结果页会走普通分组并搬窗，导致后台捕获不返回首帧。
新增独立 `managed-result`/user 归属仅保留已验证、未固定、未分组、普通窗口
原结果页的位置；不改变其他标签的分组模式，已有任务页仍保留原来源身份。
原证明持续到认领结束，移动后移回及文档替换也撤权；重启不恢复旧权限。
该修复通过 93 项定向回归及独立差异检查，正式流程中原 root/iframe
提交点击分别在 114/130 ms 完成，没有延长原 10 秒期限。

清理发送与业务发送分开：原文档有实际销毁证明时，已发出的旧资源清理请求
迟到拒绝不再撤销存活的新文档；原 Promise 仍实际结算。仅父导航、权限撤销
或 session detach 不构成该证明，业务文件提交不使用此例外。该问题保留
真实失败诊断及先红后绿的回归；受影响 231 项检查通过。

## 集成入口与剩余边界

集成入口为 `scripts/browser-integration/managed-human-file-chooser-check.mjs`。
设置绝对路径 `OBU_TEST_HOST_BINARY`、`OBU_TEST_EXTENSION_DIR`、
`OBU_TEST_BUILD_MANIFEST`、`OBU_TEST_CHROMIUM_BINARY`，并设置
`OBU_TEST_HUMAN_FILE_CHOOSER_MODE=workflow` 后运行普通文件流程；目录流程
使用 `directory-workflow`。脚本冻结构建和测试来源，使用独立资料目录及
四个原交付页；必须完成 End 后显式恢复、重新认领和原表单唯一业务提交，
才算完整通过。

默认 baseline 仅用于旧运行时缺失普通通道诊断，`directory-baseline` 用于
目录缺口诊断；诊断完成与功能通过分别记录。额外设置
`OBU_TEST_HUMAN_FILE_CHOOSER_DIAGNOSTIC=1` 会观测原清理与动作回执，其
`featurePassed` 始终为 false，不得代替未插桩验收。

真实验收使用独立 Headless Chromium，并向查看器的原本地选择器提供文件；
不操作桌面鼠标或个人浏览器。此方式不能证明 Windows 原生文件框的焦点行为，
普通公司 Edge、其他平台和整体能力对齐仍待验证。目录能力仍为开发版，不能
将本次固定 Chromium 验收扩展为这些平台或最新已发布包的能力。
