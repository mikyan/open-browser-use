# 人工接管中的本地纯文字粘贴

用户要求继续完善 Browser Use，并重新提供 Windows 完整包；不提 PR，发布到
用户自己的 fork。完整能力对齐仍是开放目标。

原查看器阻止 Ctrl+V 的默认行为并把按键送到被控浏览器，无法得到用户本地
的粘贴文字。本轮保留粘贴快捷键的浏览器默认行为，从原 paste 事件同步读取
一次纯文字，通过原人工输入队列提交；beforeinput 不再重复提交粘贴。
原接管身份、序号、回执和撤权后丢弃待发送内容的约束保持。

直接文字输入允许严格匹配的 Shift/Control/Meta 持键，保留原按键状态与实际
释放；非修饰键和鼠标持键仍拒绝。查看器也保留组合输入期间原已登记按键的
真实释放。新粘贴入口拒绝孤立 surrogate、不支持的控制字符和超长文字。
该校验不代表所有既有普通文字和 IME 路线已经完全验证。

关键文件：`internal/managedviewer/ui/viewer.js`、相邻测试，以及扩展的
`managed-human-control.js` 和相邻测试。浏览器验收复用原 managed human runner。

固定内存剪贴板的真实 UI 诊断先复现旧版失败，再确认一次 trusted paste、
一次文本请求与原修饰键释放；其控制端是 mock，不能替代完整原生验收。
另有8组真实原生修饰键实验通过，每组两次 Unicode 多行直接输入、实际值与
原释放一致。第一次实验对 DOM input 事件数的假设过强而失败，原记录保留。
