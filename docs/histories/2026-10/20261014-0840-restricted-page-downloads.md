# Original Blob downloads on permitted websites

The user requested continued Browser Use parity development in the existing
upstream-derived project, without a PR or pointer interference. Ordinary Edge
manual authorization remains deferred at the user's request.

The extension now supports original same-origin, non-opaque Blob downloads
under website restrictions through the existing public download interfaces.
Admission fixes the original policy, attachment, root and source documents,
native default execution context and GUID. Page frame origins derived from
URLs cannot substitute for the emitter's actual origin. A registered new child
may finish only its first original commit; navigation cannot refresh an old
unadmitted source. An admitted file can survive legitimate allowed navigation.

Private claim/path/cancel/release operations now remain tracked until their
actual original replies arrive, even after the caller deadline. Pause, end and
detach drain those operations and the original attachment. These cleanup fixes
also apply to unrestricted downloads. No original click, POST or URL fetch is
replayed, and no OS input or focus restoration is added.

The new reusable acceptance mode covers JS, CLI, MCP, Python and Go across root,
existing OOPIF and dynamic OOPIF layouts, followed by ten boundary workflows.
Original native events, file paths and bytes are checked independently of API
success. Two diagnostic gates retain original replies without changing their
values. A shared Blob from an opaque emitter is blocked by Chromium before a
download event in the real test; native-event counterexamples separately prove
the missing-context defect. Neither result is misrepresented as the other.
