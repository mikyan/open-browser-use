# Original page downloads on permitted websites

- Status: completed (this slice only; full parity remains active)
- Started: 2026-10-14
- Parent: [Browser Use parity](../active/2026-10-10-browser-use-parity.md), P10/P14/P15.

## Outcome and scope

Continue the complete file-workflow goal through the existing public download
APIs. Website restrictions currently reject even a report generated by an
allowed document. Retain the original browser download, GUID and actual file;
never refetch a URL, replay a POST, or substitute fixture bytes for delivery.

The first implementation covers same-origin, non-opaque Blob reports from
proven allowed original documents. HTTP/POST downloads remain a separate open
requirement, not a completed capability: the exposed native download events do
not provide a key to their original Network request and redirect chain. Existing
unrestricted download behavior and all public API shapes remain compatible.

contains URL-chain and initiator information that these events do not expose.
GUID joins Page to Browser delivery; URL/time/filename matching does not establish
an original Network request or authorize its redirects.

## Contract

- Capture original policy, attachment and already existing frame documents at
  arm time. Same-URL navigation or document replacement cannot supply a new
  document for an old candidate. A newly attached frame needs its own original
  preparation and first-document evidence; it cannot refresh an old source.
- Fix the first native GUID and emitter synchronously. Validate its original
  frame/document and non-opaque native security origin, matching the Blob origin,
  and the complete allowed tree before exposing results or file paths.
- Retain original Native Port/generation/root target and actual claim/release
  acknowledgements. Revalidate authority after asynchronous work and before
  delivery. A retired turn or policy cannot revive the original handle.
- Cancel observation and cancel transfer remain distinct. Cleanup must not
  re-authorize a denied page or operate on a successor attachment. Timeout is not
  proof that the browser did not download a file.
- No OS pointer, input replay, foreground restoration or new focus exemption.

## Work and acceptance

1. Engine collaborator owns backend/registry implementation and deterministic
   old-source failures. Fixture collaborator owns original-file public callers
   and independent file/native evidence. Root owns runner, builds, isolated real
   browser launches and documentation; an independent auditor checks contracts
   and retained artifacts.
2. Keep a real old-source failure before claiming improvement. Use explicit
   production Browser binding through a transparent evidence relay in a separate
   focused mode. Borrow the existing settings popup; bind only after its worker
   restart checks have completed. Default full-suite browser behavior stays
   unchanged.
3. Exercise JS, CLI, MCP, Python and Go on root, existing OOPIF and dynamic OOPIF.
   A single original trusted click generates a Blob and immediately revokes its
   URL. The product path must equal the original GUID's native completed path;
   actual file bytes and document identity must match.
4. Verify rejected HTTP/POST provenance, denied/opaque sources, replaced
   documents, old scopes, policy changes and real pending operations. Retain
   failures, actual process exits and distinct cleanup outcomes.
5. Run relevant tests and full browser regression, audit exact resources and
   focus records, update capability/debt/history documents, then commit and push
   to the existing fork branch. Keep the full parity goal open.
