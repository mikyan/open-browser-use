# 原生浏览器组合输入验收

## 目标与范围

继续完整 Browser Use 能力对齐，补齐人工接管的中文组合输入证据。当前查看器
已有 compositionstart/end 与原 lease/generation 门禁，但既有正式流程中的
Unicode insertText 不产生预编辑阶段，不能证明候选更新、确认和取消的行为。

本轮先用独立 Headless Chromium 的 Input.imeSetComposition 和 insertText
驱动浏览器原生事件，再从正式 managed 查看器输入到原任务文档。它验证浏览器
组合输入路径，不替代 Windows 实际输入法、候选窗口位置或其他浏览器验收。
完整 P01–P15、普通公司 Edge 和真实输入法仍保持开放。

## 约束

- 保留现有 handoff 和 local-paste 场景；不发送合成 DOM composition 事件。
- 原任务只能接受生产 SDK 和正式查看器的操作，不对任务建立测试 CDP 输入通道。
- 不读取或修改系统剪贴板，不使用个人 profile、系统鼠标或前台激活。
- 未证明的生产缺陷不靠合成时序推断；发现真实失败时先保留，再修复和新建验收。
- 不重放业务。每场保留原请求、输入回执、文档身份、文件与实际退出证据。
