# 人工接管的输入法预编辑显示

## 目标与当前依据

继续完整 Browser Use 能力对齐。上一项离页确认已合入并推送 `67f9f9f`，
本轮起点工作树干净；上一轮属于实际进展，整体目标仍未完成。

当前正式查看器使用本地 textarea 接收原生输入法组合，确认后将一次文本
通过既有人工输入协议送入原页面。已有真实浏览器脚手架覆盖预编辑、两次
相同确认、取消、End/Resume 和 Agent 唯一业务提交，但 textarea 只有 1×1
像素且完全透明，放在画面左下角。用户看不到正在组合的文本；候选输入位置
也没有随画面内操作定位。这是实际体验缺口，不能以提交文本成功代替。

## 实现范围

- 保持同一个本地原生 textarea，在组合期间显示可读的预编辑内容。
- 以最近一次原画面点击定位本地组合区，并限制在可见区域内；不能把最近
  点击位置称为远端 caret。Tab、方向键及远端页面滚动后的准确 caret 跟随
  需要独立协议/证据，不能由截图推断。
- 本地候选与编辑仍由原输入法处理，原页面继续只收到每次最终确认的一次
  文本输入。组合中取消不提交，输入内容不写入状态栏或持久日志。
- End、失焦、弹窗、导航和 generation 变化撤销旧组合的提交资格；清空
  可见内容。保留原输入回执、暂停和清理合同，不重放组合或业务操作。
- 同步查看器过期帮助文字：离页确认已支持，但不据此扩大其他系统弹窗支持。
