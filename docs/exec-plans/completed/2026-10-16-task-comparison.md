# P15：六个完整任务的有限对照

## 目标与状态

2026-10-16：上一片已在 `e83c6d8` 完成验收并发布 Windows preview。本片
比较 Open Browser Use（OBU）正式 JS SDK 与当前 Codex Browser Use 的实际
完整任务结果，固定 **6 个任务 × 2 方 × 2 轮 = 24 次尝试**。本计划的
预算、业务说明、顺序和结果分类在执行前固定；24 次已结算并完成停止后独审。

OBU 12 项：1 blocked-environment、1 failed、10 success；Codex 12 项：1 blocked-environment、9 success、2 unsupported。

本执行计划已完成；整体 P15 与 Codex 能力对齐仍未完成。详细结果见
[两轮完整任务对照](../../references/paired-task-comparison.md)。

这不是模型推理能力或通用网页性能基准。两方均从公开任务页、渲染后的资料
和自己的正式浏览器 API 完成任务。既有回归 driver、fixture checker、私有
oracle 只供准备环境和事后审计，不得作为 OBU 的解题器。旧版成功记录不能
填入本表；API 文档存在也不能代替本轮完成证据。

## 固定范围与双方入口

OBU 使用冻结提交和构建的正式 `open-browser-use` JS SDK。Codex 使用本轮
实际 `mcp__cua_repl` 返回文档中的 API；当前环境的 native computer APIs
disabled，不使用系统鼠标、键盘或人工操作代完成任务。优先使用隐藏 IAB
测试页。创建页、上传、下载、诊断的真实可用性均由本轮尝试决定。

每次使用新任务 key 和独立业务账本。六项保持 variant 3 表单、variant 3
研究、root 多文件上传、root POST 下载、root Blob 下载、root/跨源 frame
诊断，不增加浏览器品牌、SDK、布局或故障组合。普通安装 Edge 人工授权、
macOS、BFCache、目录上传与性能优化不在本片内。

准备阶段只能查正式 API 文档、建立连接、在任务外空白页检查运行时健康、
准备公共测试文件和被动观测。不得预先浏览正式任务或进行会产生业务效果的
演练。首次打开任务 URL 或首次业务工具调用（取较早者）开始计时。

输入。launch card 不携带 private stats、源码中的 expected 值、元素路径、
答案表或预编排的操作步骤。页面需要补充任务说明时，薄 server 应对双方
展示同一文字，不改变业务控件、业务处理或成功条件。

## 同题与解题隔离

研究 fixture 默认按随机 nonce 生成材料。比较模式必须为每轮冻结一个随机
材料种子，同轮 OBU/Codex 使用不同 key 和独立提交账本，但公开数值、报价
修订、合规分支与布局相同。来源 URL、case key、receipt ID 可以不同，不能
据此判失败。第二轮使用另一份材料，不能重用第一轮答案。默认随机 server
行为保持，比较模式的 ready 只发布四个任务 URL 和环境身份，不发布种子、
oracle、答案或合规结论。材料一致性由准备/审计侧验证，不送给 solver。

表单的公开要求完全相同。上传文件完全相同。下载允许独立 case nonce 和
一次性 token 使实际内容不同，但固定同类型、root 布局和字节构成规则，分别
对自己的原响应核验，不按文件名或时间猜文件归属。诊断事件内容与路由结构
相同，来源的 attempt key 和端口可以不同。

正式执行采用双方各一个不继承准备/审计上下文的独立 solver，仅给 launch
card、正式 API 文档、任务 URL、公共上传文件和本方连接参数。双方各自可
保留自身上一轮经验，第二轮研究材料更新；不能互传答案或获得审计提示。
准备者、源码评审者和 oracle 审计者不亲自解题，不把观察到的答案或 selector
程序发送给 solver。若隔离失效，该行明确记录，不能称为盲测。

允许：从正式 API 读取当前可见 DOM、可访问树、截图、输入值和任务的公开
收据；依据这些观察选择 locator 或进行算术；使用公开下载/文件/诊断 API。
通用记录器可包裹 API，但不能包含任务答案、fixture 专用选择器或解题流程。

禁止：导入 `formWorkflowSteps()`、研究 driver、`check*()`、expected/oracle；
读取 fixture 源码/本地 server 证据/基础设施原始 stdout（下载 ready 含私有
payload）/私有管理 URL；读取隐藏业务闭包、脚本
config 或原型注入；通过 evaluate 改值/派发事件/直接 fetch 业务 POST；直接
使用宿主 CDP、filesystem 或 native debugger 绕过本方正式接口完成业务。
上传读公共输入、下载结束后读工具交付文件、被动审计读原证据属于明确例外。

## 结果分类与证据契约

每行必须有一个最终任务状态，同时独立记录 `cleanup`、`interference` 和
证据完整性；不能用业务成功覆盖未确认的资源清理。

| 状态 | 使用条件 |
|---|---|
| success | 预算内完成全部业务要求，原收据/文件/诊断和必要页终态可核验；没有业务重放。 |
| unsupported | 当前正式接口明确不提供必需能力，或原调用明确返回不支持；记录具体缺口及已完成部分。只有文档未列出、一次超时或工具报错不足以推断 unsupported。 |
| failed | 原操作报错、错误业务结果、重复提交、错误文件/来源、超预算前主动停止，或无法提供必要成功证据。保留原错误，不重分类成不支持。 |
| timeout | 共同时限耗尽，包括等待真实业务或工具结果。记录在途调用，随后仅清理。 |
| blocked-environment | API/runtime/server 在任务开始前或运行中不可用、权限缺失、外部干预等，明确证据；占用该预定行，不悄悄更换为新成功尝试。 |
| contaminated | solver 读到私有 oracle/专用 driver，或任务输入/版本/预算不一致；该行不能作为能力成功证据，保留原因。 |

所有 24 行都保留；双方各 12 行报告 success、unsupported、failed、timeout、
环境阻塞和污染数量，不删除分母。针对双方都支持的任务可以另列结果，但
不能因此宣称整体能力一致。只有两轮，不作统计显著性或性能持平结论。

每次留存 attempt ID、task URL、公开指令 SHA、paired-material ID、case key、
提交/扩展/SDK/runtime/browser 身份、模型与思考配置、起止时刻、原始工具
回执/错误/替代、API 操作数、创建/关闭/保留 tab ID、业务原请求/收据及
文件路径/字节/SHA、最终状态、清理结果和观测限制。原件以独立目录、不可
覆盖文件保存；审计结论关联原件 SHA，不把 checker 的 passed 布尔当全部证据。

wall time 从首次任务访问起连续计量。工具往返与可观察的 driver/API 执行
耗时另列；模型思考时间只有平台真实提供才填写，否则标 unknown，不能用
wall 减工具时间编造思考耗时。OBU 脚本 API 调用时间不能与 Codex 含推理的
整轮 wall time直接比较。平台、浏览器后端或控制模型不相同均列为条件差异。

## 不打扰用户与终止边界

只创建和关闭本次拥有的测试页。任务前后记录可得的用户 tabs、active tab、
窗口与焦点；OBU 沿原被动观察器记录实际事件和现有精确许可，不为得到零
结果放宽许可。Codex 记录实际可得的页面/窗口观测和创建方式；不能把
`visible:false` 或零工具激活调用当作 OS 前台完全不变的证据。没有独立
原生 OS 观测时，该层标为未测。浏览器窗口焦点与系统鼠标控制分开报告。

任务停止后不重放动作；等待原 Promise 和本方正式 End/finalize/取消/关闭
回执。清理超时或失败原样记录，不能将取消意图当完成；未知资源不带入下一
次尝试。研究的唯一交付报告页保留在结果快照中，之后统一清场只处理本次页。
server 用正常 `stop` 收尾，记录原进程实际退出；下载 server 的 `stopped`
输出不能替代外层进程 close。被动 observer、诊断和 server 的缺失观测标
unknown，不以更宽的成功定义掩盖。

## 决策记录

- 2026-10-16：采用六任务两轮交叉顺序，不使用已有回归 driver 给 OBU 解题。
